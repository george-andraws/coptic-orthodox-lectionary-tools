# Package-to-site lectionary review

Use this workflow for a read-only review spanning npm data, builders, and a deployed consumer.

- Download the explicitly requested npm version with `npm pack --pack-destination <review-dir>` and byte-compare every tar member with the local package. A local tarball or package manifest alone does not prove what is published.
- Keep package, source/design, site dependency, local generated site assets, and live deployed assets as separate snapshots. Hash production JavaScript and compare data semantically; study metadata changes can alter daily shards without changing readings.
- Compare reverse occurrences using full context keys or multisets. `identity_key` can repeat across occasions; dictionary indexing by it silently discards rows.
- Do not call package-versus-design differences stale output until reading projection and structural-date generation. Removal metadata and date coverage can legitimately differ after these transformations.
- Trace the full static build before declaring a missing-copy bug. Quartz's static emitter copies `quartz/static` to output before post-build daily sharding; standalone data generation is not the full deployment build.
- Run artifact-level bounds, real-calendar-date, state-visibility, numeric-order, and occasion-identity checks in addition to existing verifiers. Passing hashes/counts/source-cache comparisons does not establish correct Scripture references or feast precedence.
- Compare source-backed slot metadata before and after reverse-to-daily conversion. Preserve `slot_order`, `slot_type`, and service order; test OT1/OT2/OT10 ordering with numeric comparators, plus ordinal aliases such as Third Hour/3rd Hour.
- Test current versus superseded visibility separately from provenance retention. A helper that excludes projection-removed rows may still include rows marked superseded by another field; examine real daily output rather than assuming an active helper handles every status.
- For Holy Week, test multiple occasions sharing a date and hour. Preserve eve/day context through generation, page titles, service groups, and study links. Never correct an invalid reference with a blanket string substitution when source texts assign different passages to Monday Eve and Tuesday Eve.
- Check feast-collision dates already present in source caches. A structural resolver that fills only missing keys can preserve a wrong feast assignment and omit the expected Pascha services while passing complete-calendar checks. For Annunciation precedence, consult UK Midlands Katameros Days, General Remarks §13 (`out/sources/UK_Midlands_Katameros_Days.txt:311-316`, https://ukmidcopts.org/pdf/Katameros_Days.pdf): its ordinary feast-reading precedence excludes the last Friday of Lent through the second day of the Pentecost season. Use a collision fixture such as April 7, 2026, rather than trusting the daily web cache over the printed exception.
- Exercise live searches with chapter ranges, comma-separated verses, Unicode en dashes, and trailing junk. Unsupported syntax must fail visibly, not silently narrow or concatenate references.
- Inject a transient failure for both current and fallback indexes, restore successful fetches, and retry without reloading. Rejected promise caching can make search permanently fail for the SPA lifetime.
- Audit linked Psalm study content, not just frontmatter overlap. Matching numeric metadata can hide a study quoting a different Psalm; verify against the printed numbering convention before blaming lectionary assignments.
- Block feedback/analytics write endpoints during automated failure/miss probes when possible, so audit searches do not pollute user feedback queues.
- Use Playwright from the site's existing dependencies as an isolated headless fallback when browser-harness CLI is absent. Do not install/reconfigure browser tooling unnecessarily or attach to the user's active browser for public-site QA.
- Save the consolidated report separately from reviewers' working notes and explicitly reject candidate findings disproved by parent verification.
- Re-review remediation for scope and compatibility: a narrow documented active predicate is not automatically an API contract violation because superseded markers use another field. Prefer explicit current-reading semantics without blanket historical-marker filtering; use semantic-diff allowlists for intentional corrections rather than demanding zero active-row changes.
- Run full Python unittest discovery, including reading-semantics tests, before claiming full package coverage. Missing bs4/convertdate can hide an entire module behind a green validation-only subset; use an isolated dependency environment rather than modifying Hermes's own environment.
- Test daily deduplication with the same passage and slot in two distinct occasions. Include occasion context in dedupe identity and separate prophecy-slot groups without breaking multi-segment Psalms/Gospels.
- Trace copied Pascha source tables before planning an upstream rebuild. A builder may prefer existing out/data and fall back to out2 rather than re-extracting; use a durable context-keyed correction overlay or canonical source repair, not generated-only edits.
- Keep root-query remediation consistent with its source-template role and generated-copy parity. Read the runbook before classifying the root invocation as the supported public interface.
